# 搭页面

写前端页面、做可点击原型、没有设计稿时临时补一个页面，都照这里做。规范的数值只在网站（`site/`），这里只写怎么做。

## 原型

- 用 React，组件从 `site/src/kivi/` 引（`import { Button } from '@kivi'`），不手写组件样式，不引别的 UI 库。
- 同一个控件在几处出现，先抽成一个组件再填内容。生成用的下拉、参数面板这类已经在 `site/src/kivi/generation/`（GenSelects、GenParams、ModelControls，选项在 options.ts）。
- 用户作品的位置用 `PlaceholderImage`，不放随手找的图。
- 关键状态都要能点到：空、加载、生成中、失败、禁用。
- 交互照线上产品；网站上没写的交互，标「待确认」。

## 没有设计稿时

1. **找最像的现有页面**：画布读「画布」，对话读「Agent 对话」「Agent 过程」，生成记录读「主站」，输入框读「生成」，整页怎么拼读「页面模板」。照它的结构摆。
2. **拆层**：按「设计规则」页（`site/src/docs/foundations/rules.mdx`）的「颜色和底色」「浮层」定底色和浮层。
3. **挑组件**：按「设计规则」页「按钮」最后一条判断控件类型，在 SKILL.md 的路由表里找对应页，读参数表拿尺寸和状态。
4. **补状态**：
   - 空状态用 `EmptyState`。
   - 加载：知道内容长什么样用骨架屏，不知道用转圈。
   - 失败、禁用。
   - 内容过长：截断还是换行。
   - 完整清单见 `workflows/acceptance.md` 的「状态」。
5. **说明**：交付时列出哪些地方属于「能组合」「没覆盖」（见 SKILL.md「规范没覆盖时」）。
6. **自查**：照 `workflows/acceptance.md` 的「变量和组件」「状态」「交互」「动效」过一遍。
