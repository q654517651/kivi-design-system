# KIVI 设计规范

来自 Figma「KIVI UI KIT V2」（草稿 0.1），设计、产品、研发共用。以 Figma 为准，Figma 里没定的不写。

## 规范在哪

规范只有一份，就是 `site/` 里的网站。这个文件只管「先读哪页、怎么做」，不写具体数值。

- **规范文字**：`site/src/docs/**/*.mdx`。每页最下面「参数」表有组件的属性和关键数值。
- **组件**：`site/src/kivi/<页>/`，`.tsx` 看属性，`.css` 看实际尺寸和用了哪些变量。
- **数值**：只在 `site/src/kivi/tokens.css`。要哪个值，查这里的变量名。
- 本文件和网站对不上时，以网站为准。
- 想看效果：在 `site/` 下 `npm install`、`npm run dev`，打开 `http://localhost:4173/`。

## 先分清是哪种任务

| 任务 | 怎么做 |
|---|---|
| 写前端代码（任何栈） | 样式只用 `tokens.css` 的变量。网站里有的组件，照它的属性、尺寸、状态实现；React 项目可以直接用 `src/kivi/` 的组件。 |
| 可点击原型 | 见下面「原型」。 |
| 没有设计稿，直接开发 | 见下面「没有设计稿时」。 |
| 审查设计稿或已开发页面 | 见下面「审查」。 |
| 在 Figma 里搭 | 用已发布的「KIVI UI KIT V2」库组件，颜色、间距、圆角、字号都绑变量。用户作品的位置放 PlaceholderImage 实例：先选图片，再选比例。 |
| 编辑 Figma 组件库本身 | 读 `references/figma-kit.md`。只有加组件、改变体、改名、整理页面时才读。 |

## 核心规则

数值都在网站，这里只写判断方法。

1. **只用语义变量**。颜色、间距、圆角、字号、行高、透明度、时长都用变量，不写死，不用原始色（`white/8`、`gray/900` 这类）。只有深色一套主题。Figma 名换 CSS 名：`/` 换成 `-`，前面加 `--`；小数写成横杠（`border/width/1-25` → `--border-width-1-25`）。画布连线例外。
2. **底色分层**：页面底 base → 区域 container-light-2 → 可点的 container-light-1；凹下去的用 container-dark；盖在画布上、必须不透明的用 surface。能点的悬停、按下各升一档，叠加最多两层。叠在图片、视频上的按钮和标签用 on-media。见「变量 · 底色、填充与状态」。
3. **浮层分三种**：
   - 会浮动、跟着移动、面积不大的（菜单、下拉、右键、节点工具栏、参数面板、按钮条）用玻璃：`--color-bg-fill-glass` + `--effect-glass-blur` + 1px `--color-border-subtle`。
   - 模态弹窗用 surface，下面一层 mask。
   - Tooltip、Toast 用 popup 实色。
   - 浮层都不加投影。
4. **字号**：界面 13，阅读 14。哪种文字用哪档，见「变量 · 文字样式」。字体苹方。
5. **尺寸**：间距、圆角、控件高度只用变量和网站上有的档位，不自己发明新值。
6. **品牌色省着用**：只给主操作、选中、开关打开、进度。主要按钮（品牌渐变）一屏只放一个。单选列表的当前项用「选中」底色，不打勾；勾选只给多选。
7. **先分清「做动作」还是「选值」**：做动作用 Button / IconButton；几个值选一个用分段（TabItem）；值多或文字长用 Select；开关立刻生效用 Switch；范围调值用 Slider；多选用 Checkbox；切换整块内容用选项卡；只展示用 Tag。
8. **状态画全**：可交互的至少有默认、悬停、按下、禁用；需要时加选中、加载中、错误。只有图标的按钮要配 Tooltip。
9. **动效**：先按怎么动选缓动，再按动多远选时长。不用匀速和 CSS 默认 `ease`，只有循环动画（转圈、扫光）用匀速。见「动效」。
10. **组件不改样式**：业务页面用现有组件拼，不为某个页面再造新按钮、新菜单。
11. **占位值照用但要说明**：`tokens.css` 和「变量」页标了占位的值（功能色等）照用，交付时注明。

## 规范没覆盖时

先判断这件事属于哪一档，再决定怎么做、怎么下结论：

| 档 | 是什么 | 做的时候 | 审查的时候 |
|---|---|---|---|
| 已定 | 网站上写明了：变量、组件属性、参数表数值、上面的核心规则 | 照做 | 不符合就是**违规** |
| 能组合 | 没有现成组件，但能用现有组件和变量拼出来 | 用现有组件拼，交付时说明怎么拼的 | 写成**建议**，不算违规 |
| 没覆盖 | 网站上没有依据（比如整页布局、新的业务模块） | 按最像的现有页面给方案，标「规范未覆盖，待设计确认」 | 写成**未覆盖**，不判对错 |

- 不要把自己的审美偏好当规范。说不出依据在网站哪一页，就不是「已定」。
- 页面上标了「草稿」「待定」「占位」的，算已定但要注明。

## 原型

- 用 React，组件从 `site/src/kivi/` 引（`import { Button } from '@kivi'`），不手写组件样式，不引别的 UI 库。
- 同一个控件在几处出现，先抽成一个组件再填内容。生成用的下拉、参数面板这类已经在 `site/src/docs/business/generation.tsx`。
- 用户作品的位置用 `PlaceholderImage`，不放随手找的图。
- 关键状态都要能点到：空、加载、生成中、失败、禁用。
- 交互照线上产品；网站上没写的交互，标「待确认」。

## 没有设计稿时

1. **找最像的现有页面**：画布读「画布」，对话读「Agent」，生成记录和输入框读「主站」。照它的结构摆。
2. **拆层**：按核心规则第 2、3 条定底色和浮层。
3. **挑组件**：按第 7 条判断控件类型，在下面的路由表里找对应页，读参数表拿尺寸和状态。
4. **补状态**：空状态（`EmptyState`）、加载（知道内容长什么样用骨架屏，不知道用转圈）、失败、禁用、内容过长（截断还是换行）。
5. **说明**：交付时列出哪些地方属于「能组合」「没覆盖」。
6. **自查**：照下面「审查」的清单过一遍。

## 审查

### 先说清查了什么

| 拿到的 | 能查 | 不能下结论的 |
|---|---|---|
| 只有源码 | 变量、写死的值、组件用法、状态写没写 | 视觉效果、布局 |
| 截图或设计稿 | 颜色、字号、间距、圆角、层级、布局 | 悬停、键盘、动效、状态切换 |
| 能运行的页面 | 上面都能查，再加悬停、键盘、弹窗、滚动、状态切换、动效 | — |

结论开头写明这次拿到了什么、查了哪些页面和状态。没查到的范围直接写「未检查」，不要猜。

### 清单

- 颜色、圆角、字号、间距、时长都用了变量，没有写死（布局宽度除外）。
- 用了现有组件，组件的尺寸、类型、状态在网站参数表里有。
- 底色分层和浮层做法对（核心规则 2、3）。
- 字号档位对：界面 13，阅读 14。
- 一屏只有一个主要按钮。
- 只有图标的按钮都有 Tooltip。
- 状态齐全：悬停、按下、禁用、加载、空、失败。
- 动效的缓动和时长用变量，没有匀速（循环除外），没有默认 `ease`。
- 图标是 Figma 图标表里的名字和图形，不是 Lucide 或别的图标库。
- 没用旧名。遇到旧变量名、旧组件名、旧图标名，查「旧名对照」，给出新名。

### 每条问题怎么写

```
[违规 / 建议 / 未覆盖] 位置（文件:行，或截图里的区域）
现状：实际是什么（值、组件、表现）
依据：网站哪一页哪一节（未覆盖就写「网站没有」）
改法：改成哪个变量、组件或属性
```

按违规 → 建议 → 未覆盖排序。没有问题的项不用逐条列。

`site/` 下的 `npm run check` 只查组件库 `src/kivi/` 的写法和写死颜色，不能代替页面审查。
