KIVI 设计规范

KIVI 产品界面（AI 无限画布 Web 端）的组件库。设计、产品、研发、AI 看的是同一份：能直接点着试，代码能直接复制。以 Figma 为准，Figma 里没定的不写。

怎么用

  • 前端：引入 kivi/tokens.css 和要用的组件样式，照页面上的代码写结构。代码是纯 HTML + CSS，不依赖框架，React、Vue 或以后换别的都能照着写。
  • 设计：每个组件的属性面板和 Figma 右侧属性一一对应，可以拿来对照效果。
  • AI：skill 直接读这些页面和 kivi/ 里的文件，不另外维护一份 md。

文件

位置是什么前端要不要抄
kivi/tokens.css所有变量。数值只写在这里要
kivi/base.css图标的占位元素、加载转圈要
kivi/button.css 等组件样式，每个 Figma 页一个文件要
kivi/icons.js图标 SVG，从 Figma 导出看图标方案定
foundations/ components/规范页面：用途、结构、属性、样子、用法 + 演示不用，看就行
shell/这个网站自己的外壳：目录、复制、属性面板不用

和 Figma 同步

  • 目录按 Figma 的页分。Figma 改了哪一页，就改对应的页面和 kivi/ 里的文件。
  • 改变量：只改 kivi/tokens.css，页面上的值是从它读出来的。
  • 改组件：改 kivi/ 里的样式，再改页面上的说明。
  • 改名要有对照：Figma 各页的「迁移映射」。
